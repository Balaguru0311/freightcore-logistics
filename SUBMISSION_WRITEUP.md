# Assignment Write-up

I approached FreightCore as a premium enterprise logistics experience rather than a generic landing-page template. I first converted the brief into three priorities: a memorable scroll journey, a meaningful WebGL visual, and responsive behaviour across desktop, tablet and mobile. I used AI as a pair-programming tool by giving it focused prompts covering the required page structure, brand direction, animation behaviour and performance limits. Examples included asking for a primitive-based logistics network instead of a downloaded 3D model, a pinned horizontal service journey controlled by vertical scrolling, resource cleanup for Three.js, and readable panel sizing at each breakpoint. I reviewed and modified the generated React, GSAP and Three.js code instead of accepting it unchanged.

One important technical decision was to create the hero visual from Three.js primitives: an icosahedron, points and a torus route. A detailed truck model would require additional model and texture downloads, increase parsing time and make the experience dependent on external assets. The primitive-based network still communicates global freight movement while keeping the scene lightweight. I also capped the renderer’s device pixel ratio, used inexpensive unlit materials and disposed of the renderer, geometries, materials, animation frame and event listeners when the component unmounts.

The main issue appeared in the responsive service animation. My first implementation enabled the GSAP pinned horizontal movement only at widths above 900px and converted the service panels into a static vertical layout on smaller screens. Although the content remained usable, this removed the assignment’s most important interaction from mobile and tablet devices. I solved it by applying the same ScrollTrigger sequence at every screen width. Vertical swiping now controls horizontal panel movement on phones, tablets and desktops. Mobile panels use narrower responsive widths, reduced typography and adjusted spacing so the content remains readable without clipping. Users who have enabled the operating system’s “Reduce Motion” preference receive the same content without forced animation.

The finished page includes the WebGL hero, animated performance counters, the responsive pinned service journey, a control-tower route visual, fixed navigation, CTA and footer. The result is structured as reusable React components, requires no external image assets and is ready for deployment and Lighthouse testing.
